# UI 设计评审稿 V2（含智能生成流水线）

> 日期：2026-04-28
> 主题：资料生产工作台 UI 设计评审稿 — 含 Skill 智能组合与应用内微调
> 状态：待用户审阅

---

## 1. 项目目标

把当前已跑通的资料生成流程，升级为一套清晰、稳定、可演示的产品级工作台界面。

本轮 UI 重点解决 5 个问题：

1. 用户不知道当前处于哪一步
2. 用户看不清系统正在处理什么
3. 工作台主预览不够像成品
4. Skill 能力没有傻瓜化，用户不知道能生成什么、怎么生成
5. 生成结果不可微调，要么全盘接受要么重新来

一句话目标：

> 把当前 MVP 从"能跑通的原型"升级为"像真正工作台产品的可演示版本"，并把 Skill 生成能力傻瓜化。

---

## 2. 设计目标

改造后的界面需要达到以下结果：

1. 首页能快速开始项目
2. 顶部能持续显示项目上下文和流程位置
3. 每一步页面都明确输入、处理中状态和输出结果
4. 工作台页成为核心视觉中心
5. 用户上传资料后，通过简单分类选择，系统能自动组合 Skill 能力生成成品
6. 生成结果可预览，组件可选中，自然语言可微调
7. 图片生成、导出、配置等关键动作都有明确反馈

---

## 3. 设计原则

1. 流程优先：界面必须围绕主流程展开
2. 信息层级清楚：主任务、当前状态、关键结果第一眼可见
3. 工作台中心化：中间预览舞台始终是视觉中心
4. 状态可感知：所有关键模块都有空态、处理中、成功、失败、可重试反馈
5. 组件复用：按钮、卡片、步骤条、表单、状态提示等统一设计
6. 傻瓜优先：用户不需要知道 Skill 是什么，只需要选类型、看推荐、点生成
7. 渐进开放：默认全自动，高级用户可调开关
8. 预览即修改：看到成品就能选组件、说人话微调

---

## 4. 视觉方向

整体界面采用"专业工作台感"方向。

### 视觉关键词

- 稳重
- 清晰
- 信息密度高但不混乱
- 像真实生产工具，不像营销页
- 低花哨度，高结构感

### 不采用的方向

- 不走发布会式大秀场风格
- 不走极简到过轻的顾问页风格
- 不用重渐变、大面积炫光、装饰性图标堆砌

### 色彩策略

- 外层背景：温和浅底色
- 卡片背景：白底或接近白底
- 文字主色：深灰近黑
- 次级文字：中灰
- 强调色：单一冷色或深色，只用于当前阶段、主按钮、关键状态和当前选中项

---

## 5. 用户主流程

主流程：

`上传资料 → 选择资料类型 → 系统理解 → 智能配置生成方案 → 生成成品 → 预览微调 → 导出`

对应页面：

1. 首页 — 启动入口
2. 导入页 — 上传资料
3. 类型选择页 — 选资料类型，系统推荐 Skill 组合
4. 理解页 — AI 理解结果
5. 生成配置页 — 查看和调整生成方案
6. 生成进度页 — 后台调用 Skill 生成 + 图片自动生成
7. 工作台页 — 高级编辑入口
8. 预览微调页 — 应用内预览 + 组件选中 + 自然语言微调
9. 导出页 — 导出 HTML / PDF
10. 设置页 — 模型配置

---

## 6. 全局框架设计

全局框架由三部分组成：

1. 顶部总控条
2. 页面主内容区
3. 全局反馈层

顶部总控条承担产品名、当前项目、阶段导航、系统入口展示。
页面主内容区根据当前页面切换内容。
全局反馈层负责 toast、弹窗、加载遮罩、错误提示等系统级交互。

## 7. 顶部导航设计

### 左侧品牌区

- 产品名称：`资料生产工作台`
- 当前项目名
- 项目未加载时显示默认提示

### 中部流程区

- 阶段条：`上传资料 / 理解资料 / 组织结构 / 生成版式 / 导出成品`
- 当前阶段高亮
- 已完成阶段弱高亮
- 未开始阶段低对比

### 右侧系统入口

- 设置
- 图片服务状态
- 导出快捷入口

设计目标：

- 让用户随时知道当前任务位置
- 强化"流程工作台"而不是"单页面工具"

## 8. 页面级设计

### 8.1 首页

目标：让用户快速进入项目创建和项目继续。

必须包含：

1. Hero 区
   - 主标题说明产品价值
   - 副标题说明流程能力
   - 主按钮：`新建项目`

2. 常用资料类型区
   - 汇报材料
   - 招商方案
   - 产品介绍
   - 长图/信息页

3. 最近项目区
   - 项目名称
   - 当前阶段
   - 快速继续入口
   - 无项目时显示空态提示

设计重点：
- 操作明确
- 首屏信息精简
- 不堆太多说明性内容

### 8.2 导入页

目标：完成资料进入系统。

必须包含：

1. 拖拽/点击上传区
2. 文件列表
3. 文件格式说明
4. 文件解析状态
5. 下一步操作

状态反馈：

- 空态：未上传资料
- 处理中：正在解析
- 成功态：已完成导入
- 失败态：解析失败并可重试

设计重点：
- 用户必须知道"哪些文件进来了"
- 用户必须知道"系统是否真的读到了内容"

### 8.3 类型选择页（新增）

目标：上传资料后，让用户快速告诉系统"我想做哪种东西"。

必须包含：

1. 资料类型选择卡片
   - 招商方案
   - 汇报材料
   - 产品介绍
   - 培训课件
   - 宣传海报
   - 长图/信息页

2. 每个类型卡片显示
   - 类型名称
   - 一句话描述
   - 推荐的大致页数范围

3. 选择后自动展示推荐生成方案摘要
   - 将使用哪些 Skill 能力
   - 预计生成页数
   - 默认风格方向

4. 页面动作
   - 确认类型，进入下一步

设计重点：
- 卡片大、文案短、选择快
- 用户不需要理解 Skill，只需要选类型
- 选完后系统才展示推荐方案，不要一开始就展示技术细节

### 8.4 理解页

目标：把 AI 结果从黑盒变成可读结果。

必须包含：

1. 原始资料摘要
   - 已导入文件概览
   - 关键内容来源说明

2. AI 理解结果区
   - 主题总结
   - 关键信息提炼
   - 风险与缺失提示

3. 操作区
   - 重新理解
   - 确认进入下一步

4. 状态反馈
   - 理解中
   - 理解完成
   - 理解失败
   - 无结果时提示

设计重点：
- 不只显示"已理解"
- 要显示"理解成了什么"

### 8.5 生成配置页（新增）

目标：让用户看到系统推荐的生成方案，并可调整。

必须包含：

1. 方案总览
   - 资料类型名称
   - AI 理解的主题摘要
   - 建议页数

2. Skill 能力开关区
   每个 Skill 能力显示为一行开关卡：
   - 封面生成（baoyu-slide-deck）
   - 内容配图（image-studio / article-batch-illustration）
   - 图表生成（chart-image）
   - 交互原型（huashu-design）
   - 幻灯片生成（ppt-image-first）

   每行包括：
   - 能力名称
   - 一句话说明当前会做什么
   - 开/关切换
   - 默认状态由系统根据类型推荐

3. 生成参数区
   - 目标页数（可调）
   - 风格倾向（简约/商务/创意等）
   - 图片自动生成（默认开启，使用 image2）
   - 图片质量选择（标准/高清）

4. 页面动作
   - 开始生成
   - 返回修改类型

设计重点：
- 默认状态就能直接点生成，不需要调任何东西
- 开关区和参数区对高级用户开放，但默认折叠或弱展示
- 生成参数尽量少，不要做成配置表单

### 8.6 生成进度页（新增）

目标：让用户知道后台正在做什么。

必须包含：

1. 生成进度展示
   - 总进度条
   - 当前步骤说明
   - 每个步骤的状态（等待中/进行中/已完成/失败）

2. 步骤明细
   - 分析资料结构
   - 生成页面内容
   - 生成配图（image2）
   - 组装成品
   - 微调准备

3. 页面动作
   - 生成完成后自动进入预览
   - 生成失败可重试

设计重点：
- 让用户知道每一步在干什么
- 图片生成状态单独展示，因为耗时最长
- 不要让用户面对空白等待屏幕

### 8.7 工作台页

目标：核心生产界面，保留原左中右结构，兼作高级编辑入口。

1. 左栏：资料与结构
   - 文件列表
   - 文件类型
   - 页面结构列表
   - 当前页定位

2. 中栏：预览舞台
   - 预览控制条
   - 版本切换
   - 状态提示
   - 主预览画布
   - 页面成品预览
   - 图片卡槽
   - 空态/生成态/完成态

3. 右栏：操作面板
   - 内容优化动作
   - 风格统一动作
   - 问题检查入口
   - 图片生成模块
   - prompt 展示与编辑
   - 输出设置
   - 生成按钮

设计重点：
- 中栏必须是视觉中心
- 左栏负责上下文，右栏负责动作
- 三栏职责不混乱

### 8.8 预览微调页（新增）

目标：让用户看到成品并能用人话微调。

必须包含：

1. 预览区
   - 完整成品预览
   - 页面缩略图导航
   - 当前选中页高亮

2. 组件选择
   - 点击预览区任意组件即选中
   - 选中后显示组件类型（标题/正文/图片/图表等）
   - 选中后可操作：修改文字、替换图片、调整位置

3. 自然语言微调输入
   - 底部或侧边输入框
   - 用户用自然语言描述想要的修改
   - 例："把这页的标题改大一点"、"换个更商务的配图"、"这页去掉"
   - 提交后后台调用 Skill 重新生成对应部分

4. 微调历史
   - 展示每次微调的描述和结果
   - 可撤销回上一版本

5. 页面动作
   - 确认成品，进入导出
   - 重新生成整份

设计重点：
- 预览区要像真正的成品，不是线框
- 选中组件后操作要轻量，不要弹出重型编辑器
- 自然语言是核心交互，输入框要醒目且易用

### 8.9 导出页

目标：明确交付 HTML 和 PDF。

必须包含：

1. 项目摘要
   - 名称、页数、风格

2. 导出格式选择
   - HTML 文件
   - PDF 文件（从 HTML 转换）
   - 可同时选择

3. 导出动作与反馈
   - 导出进度
   - 导出成功/失败
   - 打开文件/打开目录

### 8.10 设置页

目标：完成模型与图像服务配置。

必须包含：

1. 理解模型配置
   - API Key
   - Base URL
   - 模型名

2. 图片模型配置
   - API Key
   - Base URL
   - 模型名

3. 配置校验
   - 连通性测试
   - 当前状态提示
   - 保存反馈

## 9. 智能生成流水线

### 用户视角完整流程

1. 进入首页，点新建项目
2. 上传资料文件
3. 选择资料类型（招商方案/汇报材料/...）
4. 系统根据类型推荐 Skill 组合，展示生成方案
5. 用户可调整开关和参数，或直接点生成
6. 系统后台调用 Skill 生成内容 + image2 生成配图
7. 生成完成，自动进入预览
8. 用户在预览中点选组件，用自然语言微调
9. 满意后导出 HTML / PDF

### 系统视角 Skill 调用链

1. 理解资料 → understanding-service
2. 组织结构 → structure-service
3. 生成页面内容 → baoyu-slide-deck / ppt-image-first
4. 生成配图 → image2（自动）
5. 生成图表 → chart-image（按需）
6. 生成交互原型 → huashu-design（按需）
7. 微调 → 自然语言解析 + 局部重新生成

### 资料类型与 Skill 默认组合

| 资料类型 | 封面生成 | 内容配图 | 图表生成 | 交互原型 | 幻灯片生成 |
|----------|----------|----------|----------|----------|------------|
| 招商方案 | 开 | 开 | 开 | 关 | 开 |
| 汇报材料 | 开 | 开 | 开 | 关 | 开 |
| 产品介绍 | 开 | 开 | 关 | 开 | 开 |
| 培训课件 | 开 | 开 | 关 | 开 | 开 |
| 宣传海报 | 开 | 开 | 关 | 开 | 关 |
| 长图/信息页 | 开 | 开 | 开 | 关 | 关 |

## 10. 重点模块要求

### 10.1 顶部总控条

必须承载：

1. 产品名
2. 当前项目名
3. 阶段流程条
4. 设置入口
5. 服务状态入口

### 10.2 类型选择模块

- 类型卡片要大、文案短
- 选完后即显示推荐方案摘要
- 推荐方案不让用户配置，只让用户确认

### 10.3 智能生成配置模块

- 默认状态 = 可直接生成
- 开关和参数折叠在"更多选项"后
- 图片生成默认走 image2，无需用户配置

### 10.4 生成进度模块

- 不用空白等待
- 分步骤展示进度
- 图片生成单独标注耗时

### 10.5 预览微调模块

- 预览即成品渲染
- 组件可点击选中
- 自然语言输入框核心交互
- 支持撤销

### 10.6 图片生成模块

- 自动生成 prompt（image2 为默认后端）
- prompt 可手动编辑
- 生成模式、尺寸、风格可选
- 生成中/成功/失败状态完整

## 11. 状态规范

每个关键模块都应定义统一状态：

1. 默认态
2. 空态
3. loading 态
4. 成功态
5. 失败态
6. 禁用态
7. 已完成态
8. 可重试态

特别需要完整状态设计的模块：

| 模块 | 空态 | loading | 成功 | 失败 | 可重试 |
|------|------|---------|------|------|--------|
| 文件导入 | 未上传资料 | 正在解析 | 已完成导入 | 解析失败 | 重新上传 |
| AI 理解 | 待理解 | 理解中 | 理解完成 | 理解失败 | 重新理解 |
| 类型选择 | 未选择 | — | 已选择 | — | 重选 |
| 生成配置 | 待确认 | — | 已确认 | — | 重新配置 |
| 生成进度 | 等待中 | 生成中（分步） | 生成完成 | 生成失败 | 重新生成 |
| 预览加载 | 加载中 | 渲染中 | 预览就绪 | 加载失败 | 重新加载 |
| 微调 | 待输入 | 微调中 | 微调完成 | 微调失败 | 重试/撤销 |
| 导出 | 待导出 | 导出中 | 导出成功 | 导出失败 | 重新导出 |
| 设置 | 未保存 | 保存中 | 保存成功 | 保存失败 | 重新保存 |

## 12. 文案设计

文案应从"开发提示"升级为"产品语言"。

需要统一的文案类型：

1. 主按钮文案
2. 状态提示文案
3. 空态提示文案
4. 错误文案
5. 成功反馈文案
6. AI 结果说明文案
7. 操作引导文案

文案原则：

- 简短
- 明确
- 可执行
- 少技术术语

5. 全局状态规范

### P2

1. 视觉细化
2. 文案统一
3. 响应式压缩规则

## 17. 验收标准

本轮 UI 达标的判断标准：

1. 用户能顺畅完成主流程：上传 → 选类型 → 看方案 → 生成 → 预览微调 → 导出
2. 选完类型后，系统推荐方案用户能看懂，不需要懂 Skill 技术
3. 生成过程有步骤进度，不是空白等待
4. 预览区像成品，组件可选中，自然语言可微调
5. 每页有明确主任务和下一步
6. 关键状态都有反馈
7. 界面风格统一，不再像多个独立页面拼接

---

## 18. 结论

本 UI 设计方案的核心不是把每一页单独美化，而是建立一套完整的资料生产工作界面系统，同时把 Skill 生成能力傻瓜化。

它应同时满足：

- 流程清楚
- 状态明确
- 核心工作台突出
- 操作路径稳定
- 后续扩展方便
- 任何人都能用，不需要懂技术

V2 在 V1 基础上新增了 3 个核心能力：

1. **类型选择 + Skill 自动组合**：用户选资料类型，系统推荐生成方案
2. **生成进度可视化**：让用户知道后台在做什么
3. **预览 + 自然语言微调**：看成品、选组件、说人话改内容

这 3 个能力让整个工具从"技术人员调参数"变成"任何人都能用"。
